# Contributing to Active Inference Institute projects

Thank you for helping. This guide applies to every repository in the [ActiveInferenceInstitute](https://github.com/ActiveInferenceInstitute) organization unless a repository has its own `CONTRIBUTING.md`, which takes precedence.

## Ways to contribute

- **Ask or discuss**: open an issue, use a repository's Discussions tab where enabled, or join [Discord](https://discord.activeinference.institute).
- **Report a problem**: open an issue with steps to reproduce, what you expected, and what happened.
- **Improve docs, code, or data**: open a pull request (see below).
- **Join a program**: volunteering, internships, fellowships, and more are listed at [activeinference.institute/get-involved](https://activeinference.institute/get-involved/).

## Pull requests

1. Fork the repository (or create a branch if you have write access).
2. Make focused changes on a descriptive branch, e.g. `docs/fix-install-steps`.
3. Run the repository's tests or checks if it has them.
4. Open a pull request against the default branch describing what changed and why, and link related issues (`Closes #123`).
5. Respond to review comments; a maintainer will merge when ready.

Default branches are protected against force-pushes and deletion.

## Style

- Follow the conventions already used in the repository you are editing.
- Write clear commit messages in the imperative mood ("Add", "Fix", "Update").
- Keep pull requests small enough to review.

## Licensing and attribution

Contributions are released under the license of the repository you contribute to (see its `LICENSE` file). Only submit work you have the right to share, and credit sources you build on.

## Conduct

All participation is governed by our [Code of Conduct](CODE_OF_CONDUCT.md).

## Security

Do not open public issues for security vulnerabilities; follow the [security policy](SECURITY.md).
