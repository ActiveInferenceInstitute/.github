# The public readiness ledger

[`../standards/public-ledger.json`](../standards/public-ledger.json) is the published record of
fleet readiness. This repository is public, so the ledger may carry **every public repository's**
full result and only **aggregate counts** for private repositories. No private repository name,
URL or content may appear in it.

> **Never hand-edit `standards/public-ledger.json`.** It is generated by
> `scripts/build_public_ledger.py` from a fleet report and the scope table. An edit that is not
> reproduced by the builder is a bug; change the builder or the criterion, then regenerate.

## Building it

```bash
# 1. Measure the fleet into a report (needs the scope table and each working copy)
uv run python scripts/check_readiness.py --all --scope /path/to/scope.tsv --root /Volumes/GitVault --json > /tmp/fleet-report.json

# 2. Build the ledger from that report
uv run python scripts/build_public_ledger.py \
  --report /tmp/fleet-report.json \
  --scope /path/to/scope.tsv \
  --out standards/public-ledger.json
```

Exit `0` means the ledger was written (or printed with no `--out`). Exit `2` means a usage,
scope or report error — including a boundary violation, which refuses to write rather than
publishing a leak.

## Schema

The ledger schema is `aii-readiness-ledger/v1`. Its status vocabulary is exactly the checker's
five statuses (`pass`, `fail`, `waived`, `unavailable`, `not-applicable`). Entries identify
repositories as `OWNER/REPO` and never as a bare quoted name — a bare name could collide with
the catalogue's `forbid` pattern, which matches `aii-[a-z]+` case-insensitively and therefore
also matches the *public* `aii-org`.

## How visibility is decided

Visibility comes from the **scope table**, never from a disk walk or a language guess. A scope
row is public when its relative path carries the `Public` segment and private when it carries
`Private`; a row with neither segment is a configuration error and stops the build. That makes
the public/private split a configuration fact that can be reviewed, not an inference.

## Proving the boundary

`ORG-LEDGER-PUBLIC-ONLY` asks whether the shipped ledger matches the catalogue's `forbid`
pattern. The wider gate is:

```bash
uv run python scripts/check_ledger_boundary.py \
  --ledger standards/public-ledger.json \
  --scope /path/to/scope.tsv
```

It scans the ledger against the scope table and fails on **any** occurrence of a private
repository name or repository URL, quoted or not, and it applies the catalogue's `forbid`
pattern too — so a ledger that would fail the criterion is rejected before publication. Exit
`0` is clean, `1` prints every finding, `2` is a usage/scope/catalogue error.

Because the boundary command needs a scope table it is an **owner-operated** check: it runs
where the private scope lives. The public CI gate runs the criterion-level version instead and
cannot prove the wider claim on its own. See [`standard.md`](standard.md) for the tier rules and
[`../standards/README.md`](../standards/README.md) for the human contract.
